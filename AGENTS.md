# AGENTS.md

Инструкция для ИИ-агентов, работающих с этим репозиторием.

## Что это за проект

MyHandy — однофайловая утилита голосового ввода для Linux: пишет аудио с микрофона через `arecord`, распознаёт речь локальной ONNX-моделью (GigaAM v3 E2E CTC, русский язык, через библиотеку `onnx_asr`) и вставляет распознанный текст в активное окно эмуляцией Ctrl+V. Unix-way реинкарнация [Handy](https://github.com/cjpais/Handy).

Весь код — `myhandy.py` (~110 строк). Нет тестов, линтера, CI.

## Команды

```bash
uv sync                    # установить зависимости (.venv уже в репо не хранится, но есть uv.lock)
uv run myhandy.py          # первый запуск: старт демона + немедленное начало записи
uv run myhandy.py          # повторный запуск: отправить SIGUSR1 демону → toggle записи (стоп/распознать или снова старт)
uv run python -m py_compile myhandy.py   # единственная автоматическая проверка синтаксиса
```

Системные зависимости (Debian/Ubuntu): `alsa-utils` (`arecord`, `aplay`), `libnotify-bin` (`notify-send`). Для `evdev` пользователь должен быть в группе `input`.

## Архитектура и поток управления

Один процесс-демон, управляемый сигналами:

1. При старте проверяется lock-файл (`/tmp/myhandy.lock`, содержит PID). Если процесс жив — новому запуску остаётся только послать ему `SIGUSR1` и выйти; если lock протух — удаляется.
2. Создаётся lock-файл, навешивается handler на `SIGUSR1`, загружается модель ASR (медленно, поэтому до первого сигнала).
3. Каждый `SIGUSR1` — toggle: нет записи → `arecord` пишет WAV (16 kHz, mono, S16_LE); идёт запись → процесс терминируется, файл распознаётся, текст вставляется.
4. Вставка: `pyperclip.copy()` + эмуляция Ctrl+V. На Linux — через `evdev.UInput` (работает в Wayland, в отличие от pyautogui); на Windows/macOS — `pyautogui.hotkey`.
5. Если распознан exit-word (`Выход.` по умолчанию) — демон удаляет lock и завершается.

Платформенно-зависимые импорты (`evdev` vs `pyautogui`) разрешаются на уровне модуля через `sys.platform` — держать так же.

## Конфигурация

Все настройки — переменные окружения, читаются `os.getenv` в начале `myhandy.py`: `LOCK_FILE`, `WAVE_FILE`, `ARECORD_CMD`, `BEEP_CMD`, `NOTIFY_CMD`, `EXIT_WORD`, `MODEL_NAME`, `MODEL_PATH`, `MODEL_QUANT`. Значения `*_CMD` парсятся через `.split()` — аргументы с пробелами в них не поддерживаются.

Файл `.env` в корне проекта подгружается `load_dotenv()` на уровне модуля (реальные env-переменные имеют приоритет над `.env`; `.env` ищется относительно текущей директории — как и `./models`, так что скрипт должен запускаться из корня проекта).

## Модели

`models/` в `.gitignore` (файлы >100MB). При первом запуске модель `gigaam-v3-e2e-ctc` скачивается с HuggingFace (~215MB), далее берётся локально: `config.json`, `v3_e2e_ctc_vocab.txt`, `v3_e2e_ctc.int8.onnx` (при `MODEL_QUANT=int8`, по умолчанию). Список других моделей: https://istupakov.github.io/onnx-asr/usage/#supported-model-names
